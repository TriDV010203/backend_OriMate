# CLAUDE.md — Origami Community Platform

## Project overview
Clean Architecture + CQRS .NET 8 backend for an origami tutorial and community platform.
No MediatR — handlers are injected directly via DI.
Frontend: Next.js (separate repo, not in this solution).

## Solution projects
- **OrigamiPlatform.Domain** — entities, enums, exceptions. Zero external dependencies.
- **OrigamiPlatform.Application** — commands, queries, handlers, DTOs, interfaces. Business logic lives here.
- **OrigamiPlatform.Infrastructure** — EF Core, repositories, email, storage, background jobs.
- **OrigamiPlatform.API** — controllers, middleware, DI wiring, Program.cs.

## Dependency rule (NEVER violate)
```
API → Application → Domain
Infrastructure → Application → Domain
API → Infrastructure (only for DI registration in Program.cs)
```
Domain has zero dependencies. Application never references Infrastructure or API.

## Architecture rules
- Business rules live in Application Handlers — never in Controllers.
- Controllers are thin: receive DTO → call handler → return HTTP result. No if/else logic.
- All content writes must pass through `IBlockedWordService.ContainsBlockedWord()` before saving.
- `TutorialReviewHistories` is IMMUTABLE — INSERT only, never UPDATE or DELETE.
- Handlers throw `DomainException`, `NotFoundException`, or `ForbiddenException` — never return null to signal failure.

## Handler pattern
```csharp
// Command
public record SubmitTutorialCommand(Guid TutorialId, Guid AuthorId);

// Handler — constructor injection, no base class needed
public class SubmitTutorialHandler
{
    private readonly ITutorialRepository _repo;
    private readonly INotificationService _notifications;

    public SubmitTutorialHandler(ITutorialRepository repo, INotificationService notifications)
        => (_repo, _notifications) = (repo, notifications);

    public async Task<TutorialDto> HandleAsync(SubmitTutorialCommand cmd, CancellationToken ct = default)
    {
        // implementation here
    }
}

// Controller injection
public class TutorialsController : ControllerBase
{
    private readonly SubmitTutorialHandler _submitHandler;
    private readonly GetTutorialsHandler _getHandler;

    public TutorialsController(SubmitTutorialHandler submitHandler, GetTutorialsHandler getHandler)
        => (_submitHandler, _getHandler) = (submitHandler, getHandler);
}
```

## EF Core conventions
- Always use Fluent API (`IEntityTypeConfiguration<T>`) — no data annotations on entities.
- Always set `HasMaxLength` on string properties — never leave nvarchar(max) by accident.
- All PKs are `Guid` generated by the application (`ValueGeneratedNever()`), not DB identity.
- Migrations go in `Infrastructure/Persistence/Migrations/` — never modify an applied migration.
- `CreatedAt` is set in the application layer, not as a DB default.

## Key business rules (enforce in handlers)
| Rule | Constraint |
|------|-----------|
| BR-12 | Tutorial: title 5–150 chars, description 20–500 chars, active category, cover image, 3–30 steps |
| BR-13 | VIP tutorial requires Creator to have active `CreatorVipSettings` |
| BR-15 | ContributorReviewer can only Approve→Manager or RequestRevision. Cannot publish. |
| BR-16 | Only Manager can Publish or Remove a Published tutorial |
| BR-17 | `TutorialReviewHistory` — INSERT only, never update or delete |
| BR-23 | All text content must pass blocked word check before saving |
| BR-24 | VIP subscription: 30 days fixed, no auto-renewal, no refunds |
| BR-28 | FamilyProject: max 6 participants, only Free tutorials eligible |
| BR-33 | One Achievement record per User per Tutorial |
| BR-39 | FamilyProject can only be Completed when all steps have ≥ 1 completion record |

## API response format
```json
// Success: return DTO directly
{ "id": "...", "title": "..." }

// Error: always this shape (handled by ExceptionHandlingMiddleware)
{ "error": "Human-readable message" }
```
HTTP status mapping: DomainException→400, NotFoundException→404, ForbiddenException→403, unhandled→500.

## Naming conventions
- Commands: `VerbNounCommand` (e.g., `SubmitTutorialCommand`)
- Queries: `GetNounQuery` (e.g., `GetTutorialsQuery`)
- Handlers: `VerbNounHandler` or `GetNounHandler`
- DTOs input: `NounRequest` — DTOs output: `NounDto`
- No abbreviations: `CreateVipSubscriptionHandler` not `CreateVipSubHandler`

## Background jobs
Both implement `IHostedService` and are registered in `DependencyInjection.cs`.
- `SubscriptionExpiryJob` — daily at 02:00 UTC: expire VipSubscriptions where EndDate < UtcNow
- `AdBudgetDepletionJob` — every 15 minutes: end AdCampaigns where BudgetRemaining <= 0

## Do not
- Do not put business logic in controllers
- Do not use MediatR or any pipeline library
- Do not hard-delete any content — use IsDeleted flag or status transitions
- Do not expose raw EF entities from API — always map to DTOs
- Do not skip the blocked word check on any content write endpoint
